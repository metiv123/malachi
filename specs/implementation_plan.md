# מלאכי - תוכנית ביצוע למערכת עובדת

## החלטה טכנית מומלצת
לבנות MVP רשמי על Meta WhatsApp Cloud API.
לא להשתמש בספריות WhatsApp Web לא רשמיות.

## שלב 0 - אישורים לפני בנייה
צריך אישור על:
1. אפיון MVP
2. נוסחי הודעות הבוט
3. כיוון מיתוג/דמות
4. stack טכני
5. פתיחת/חיבור Meta Business ו-WhatsApp Business

## שלב 1 - Prototype פנימי
מטרה: להוכיח זרימה טכנית עם מספרי בדיקה.

רכיבים:
- שרת Node.js/Express
- Webhook לקבלת הודעות/לחיצות מ-Meta
- DB עם משפחות, קשישים, אנשי קשר ובדיקות יומיות
- Scheduler לשליחה יומית
- Worker לבדיקת חוסר תגובה אחרי שעה
- API בסיסי לאתר
- דשבורד מינימלי

תוצרים:
- אפשר להוסיף קשיש
- אפשר לקבוע שעה
- נשלחת הודעת בדיקה
- כפתור “הכול בסדר” מעדכן סטטוס
- כפתור “מצוקה” שולח התראה
- אין תגובה שעה שולח התראה

## שלב 2 - אתר נחיתה + דשבורד
רכיבים:
- דף בית
- התחברות משפחתית פשוטה
- הוספת אדם מבוגר
- סטטוס יומי
- עריכת שעה ואיש קשר
- השהיית שירות

## שלב 3 - Meta Production
- פתיחת/שימוש ב-Meta Business
- חיבור מספר WhatsApp Business
- יצירת App ב-Meta Developers
- הגדרת webhook HTTPS
- הגשת Templates לאישור
- בדיקת opt-in

## שלב 4 - Beta 5 משפחות
- רק משפחות אמיתיות שהסכימו
- ניטור ידני יומי
- תיקון תקלות
- שיפור נוסחים

## שלב 5 - Beta 50 משפחות
- התחלת שיווק אורגני מבוקר
- מנגנון שיתוף
- מדידה לפי מקור הרשמה

## Stack מומלץ
Frontend: React + Tailwind
Backend: Node.js + Express
DB: PostgreSQL/Supabase או MySQL Hostinger
WhatsApp: Meta Cloud API
Scheduler: node-cron / server cron
Hosting: Hostinger Node.js / VPS
Analytics: PostHog/GA4 בהמשך

## למה זה קל ופשוט יחסית
- אין אפליקציה למשתמשים
- הקשיש נשאר ב-WhatsApp
- אין AI מורכב בשלב ראשון
- כל הלוגיקה היא תזמון + כפתורים + התראות
- אפשר להתחיל עם דשבורד מינימלי מאוד

## מוקשים שחייבים לפתור מראש
1. Opt-in ברור של הקשיש
2. Templates מאושרים ב-Meta
3. הודעות לא שיווקיות כדי להישאר Utility
4. לא להבטיח הצלת חיים
5. מנגנון opt-out
6. לוגים ואחריות במקרה של תקלה
7. לא לשלוח התראות כפולות
