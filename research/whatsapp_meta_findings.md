# מלאכי - תחקיר WhatsApp/Meta Cloud API

## מסקנה
הדרך הנכונה והיציבה ל-MVP היא WhatsApp Business Platform / Meta Cloud API, לא אוטומציה לא רשמית של WhatsApp Web.

## עובדות קריטיות מתוך תיעוד Meta
1. Cloud API מאפשר שליחת הודעות טקסט, מדיה, הודעות אינטראקטיביות ו-Webhooks.
   מקור מקומי: `malachi/research/meta_about_platform.md`
2. הודעות מחוץ לחלון שירות של 24 שעות חייבות להיות Template Messages מאושרות מראש.
   מקור: `meta_templates.md`, `meta_service_messages.md`
3. חלון שירות של 24 שעות נפתח כשמשתמש שולח הודעה/לוחץ תגובה לעסק. בתוך החלון אפשר לשלוח הודעות חופשיות; מחוץ לחלון רק Templates.
   מקור: `meta_service_messages.md`
4. חובה Opt-in לפני שליחת הודעות WhatsApp. צריך לציין שם עסק, מה המשתמש מקבל, ודרך יציאה.
   מקור: `meta_optin.md`
5. כפתורי תגובה קיימים: Interactive Reply Buttons מאפשרים עד 3 תשובות; Utility Templates תומכות גם ב-Quick Reply buttons.
   מקור: `meta_interactive_buttons.md`, `meta_utility_templates.md`
6. תמחור Meta מ-2025 הוא לפי הודעת Template שנמסרה; הודעות שאינן Template מוגבלות לחלון השירות.
   מקור: `meta_pricing.md`

## השלכה למלאכי
- הודעת הבוקר לקשיש = Template Utility יומית עם כפתורים.
- התראת “מצוקה” לקרוב = Template Utility, כי היא יכולה להישלח בכל שעה.
- התראת “אין תגובה שעה” לקרוב = Template Utility.
- הודעת אישור אחרי לחיצה “הכול בסדר” יכולה להיות Service Message חינמית/רגילה בתוך 24 שעות.

## סיכונים
- אם Meta תסווג את ההודעה כ-Marketing במקום Utility, העלות והאישור עלולים להשתנות.
- ניסוח חייב להיות שירותי, לא שיווקי.
- אם משתמשים מדווחים/חוסמים, איכות המספר תרד ויכולים להיות מגבלות.
- חייבים הסכמה ברורה גם של הקשיש וגם של הקרוב.

## המלצת MVP
לבנות קודם גרסה טכנית קטנה עם:
- WhatsApp Cloud API test number
- שרת webhook ציבורי HTTPS
- DB פשוט
- תזמון יומי
- דשבורד משפחתי בסיסי
- בדיקה עם מספרי טלפון מאושרים בלבד
אחרי הוכחת זרימה — להעביר למספר עסקי, להגיש templates, ולהפעיל בטא סגורה.
